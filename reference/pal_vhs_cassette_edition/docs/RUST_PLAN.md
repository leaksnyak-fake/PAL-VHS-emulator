# Rust migration and next improvements

## Goal and boundary

Accelerate the sampled PAL/VHS signal path while preserving its behaviour,
repeatable tape damage, JSON settings, Easy controls, and CLI exports. Measure
the speedup rather than assuming Rust will make this pipeline real time.
The current implementation uses many already-native SciPy/NumPy operations;
the likely gains come from fewer allocations, fused passes, cheaper field
transfer, reusable buffers, and bounded scheduling.

First retain the Python/PySide6 application and move the renderer to a Rust
extension. A full native application is a later milestone after signal parity.
This avoids changing DSP, UI, and media handling simultaneously.

## Proposed workspace

| Crate | Responsibility | Existing source |
|---|---|---|
| `pal-vhs-model` | Versioned parameters, presets, validation, deterministic event descriptors | `params.py`, `experience.py` |
| `pal-vhs-dsp` | SOS filtering, interpolation, modulation, analytic demodulation, reusable buffers | `dsp.py` |
| `pal-vhs-signal` | PAL timing/burst, colour-under, tape mechanics, decoder | `consts.py`, `pal.py`, `vhs.py` |
| `pal-vhs-render` | Field/frame requests, cancellation, bounded native thread pool | `pipeline.py` |
| `pal-vhs-python` | PyO3 boundary, NumPy buffer transfer, Python error mapping | replacement renderer adapter |
| `pal-vhs-cli` | Native offline runner and FFmpeg orchestration, later | `__main__.py`, `export.py`, `video_io.py` |

Dependency direction: Python/CLI → render → signal → DSP/model. The DSP crates
must not import GUI, FFmpeg, or Python bindings. UI descriptions and macro
definitions should eventually be generated from the versioned model schema so
they cannot drift between implementations.

## Stage 0 — freeze a useful baseline

Save synthetic colour bars, grayscale, multiburst, edge/impulse, fine-line and
moving-edge inputs. Include real licensed or user-supplied captures for SP, LP,
tracking errors and a crease. Record test conditions: source frame rate,
field order, aspect ratio, tape/deck, capture path, and any TBC/deinterlacing.

Profile **each existing stage** and allocation/IPC cost on a named machine at
720×576, both RF rates, one frame and a 250-frame export. Measure median/p95
latency, peak memory, cold-start time, throughput and UI responsiveness at 1,
2, 4, 8 workers. Separate encoding time from signal processing.

Exit: reproducible input/settings corpus, stage timings, benchmark commands,
baseline images and signal taps. Do not use the old README's timing as a new
performance claim without remeasuring it.

## Stage 1 — schema and deterministic damage

Implement typed enums, finite numeric validation, range checks and paired-value
rules such as minimum/maximum band height. Keep old parameter keys and flat JSON
import support; introduce an explicitly versioned project format for new data.
Keep unknown future fields separately or report them instead of silently losing
them during a round-trip.

Freeze all constants and scan-line conventions, including the existing whole-line
vertical-sync approximation. Document that current `Params` accepts values
between slider steps while GUI movement snaps to the grid.

Do **not** assume Rust's random generator matches NumPy's SeedSequence/default_rng
and distributions. Either port the exact generator, seed mixing and normal
sampling, or introduce a versioned deterministic event format generated by the
Python reference for comparison. A deliberate RNG change needs a visible model
version; the same seed alone is not enough for compatibility.

Exit: lossless settings migration, deterministic event schedules under random
seeking, and explicit compatibility tests across thread counts.

## Stage 2 — DSP kernels behind Python

Build the extension with PyO3 and maturin. Start with SOS filtering and
fractional displacement, then oscillator/FM modulation and analytic demodulation.
Preserve filter coefficient design and initial conditions. Match SciPy's phase,
resampling boundaries, Hilbert-transform padding, and group delays before
optimizing them. Start in f64; evaluate f32 only against measured error/noise
budgets. Neither dtype nor unsafe SIMD is an automatic optimization.

Accept contiguous field buffers and borrow them for the call; do not retain
Python-owned pointers after returning. Release the interpreter lock during pure
Rust work using the supported PyO3 API for the pinned version. Allocate owned
output, return one result per field/frame, and request optional scopes explicitly.

Proposed boundary:

```text
render_field(rgb_u8, field_index, frame_index, settings, scope_request)
    -> rgb_u8 + selected_taps + diagnostics
```

Exit: compare each noiseless stage to Python, initially targeting relative RMS
error ≤ 1e-6 in f64 kernels where mathematically identical. Set separate tolerances
for interpolation/FFT/filter changes after measuring numerical conditioning.
Rendered noiseless frames should normally differ by at most one 8-bit code for
99.9% of samples; investigate exceptions instead of loosening the budget silently.

## Stage 3 — full signal engine and scheduling

Port encoder, record, head/tape, playback, output and TV decoder in that order.
Retain automatic burst-loss/group-delay calibration and cache the expensive
filter coefficients/calibration by the subset of settings that affects them.
The current worker cache holds only one Deck; dragging controls rebuilds it.
Use immutable prepared decks plus per-job scratch buffers and frame-local damage.

Replace process-pool field serialization with a bounded native thread pool.
Use generation IDs to discard stale slider jobs, prioritize the current paused
frame, and make cancellation cooperative between stages. Put a byte budget on
frames and signal taps, not just a frame count; keep scope taps on demand.

Exit: all curated/legacy presets render without invalid values; seeking and
parallel/sequential export agree; no unbounded queue growth. Measure actual
end-to-end speedup and UI p95 response. A 2× throughput improvement is a project
target to evaluate, not a promise; 25 fps is a separate hardware-dependent goal.

## Stage 4 — media I/O and export

Keep FFmpeg as a subprocess first. Specify sample aspect ratio for 4:3 PAL,
720×576, 25 frames/50 fields, top field first; single-field exports must stay
progressive. Verify temporal field sampling on 24/25/30/50/60 fps and variable
frame-rate sources. Check audio start offsets, duration, cancellation and errors.

Write to a temporary output beside the destination and replace it atomically on
success. Never delete an existing completed user output on render cancellation.
Cap both encoded-frame queue depth and memory. Confirm FFmpeg build/distribution
licensing before bundling it. A native decoder binding can follow only when
subprocess I/O is a measured bottleneck.

Exit: ffprobe confirms interlace flags, field order, SAR, frame rate, audio sync;
cancel/failure leaves existing files intact and reports actionable errors.

## Stage 5 — full native application, if justified

Evaluate native GUI candidates with an actual cassette panel, 4:3 video view,
searchable parameter forms, accessible keyboard focus, file dialogs and live
waveform scopes. Compare startup, memory, Windows packaging, HiDPI behaviour,
and maintenance cost before choosing. Keep Python/PySide6 until the prototype
matches it. Preserve project-file migration and CLI automation.

Deliver signed Windows builds first, then test Linux/macOS separately. Pin crate
versions and keep a lockfile, reproducible build commands and dependency licenses.
GPU compute comes after CPU parity; sync locking, random damage and recursive
filters have different parallelism constraints from simple pixel shaders.

## Product work beyond the language change

1. **Real deck matching:** collect test-pattern captures and fit luminance/chroma
   bandwidth, noise spectrum, colour delay, dropout statistics and timing jitter.
   Store capture conditions and confidence with presets. Avoid fake brand names.
2. **Damage timeline:** add explicit events with frame/time, duration, strength,
   position and seed. Buttons can insert one crease/dropout at the playhead;
   clip-wide controls remain the tape baseline. Add undo/redo for all edits.
3. **Interactive cassette:** transport reel animation linked to actual playback,
   event markers, before/after toggle and a bypass comparison at the same frame.
4. **Audio model:** optional linear-track hiss, bandwidth, wow/flutter and Hi-Fi
   dropout switching, with a separate accurate passthrough option.
5. **Signal fidelity:** true half-line vertical timing, measured head azimuth
   crosstalk, more faithful dropout compensation and measured PLL behaviour.
   Each change needs a model version and regression captures.
6. **Usability:** active-preset/custom indicator, full undo/redo, paired-value
   validation, export-range selection and an explicit draft/final quality control.

## Ordering and release gates

Treat each stage as a separate reviewable milestone; schedule after Stage 0
profiling, rather than assign unsupported calendar estimates. Keep a selectable
Python backend until the Rust engine passes the corpus. Ship the faster backend
before replacing the GUI. No full rewrite is required to deliver the first speed
improvement.

Official implementation references:

- [PyO3 user guide](https://pyo3.rs/) — native extensions and Python interoperability.
- [Rust book](https://doc.rust-lang.org/book/) — ownership, concurrency and testing.
- [FFmpeg documentation](https://ffmpeg.org/documentation.html) — media/export reference.

## Edition 2 follow-through

Include `headswitch.py` in the model/signal crate boundary. Preserve the two PAL
head-channel phase sequences, per-head burst/group-delay calibration, fractional
switch timing, RF phase mismatch, and RF envelope separately from output black
masking. The new regression suite verifies nominal RF carrier frequencies and
that playback defects do not contaminate the record-FM scope tap. Preserve those
checks before optimizing precision. Prioritize true half-line PAL timing, raw
PAL reference captures, and measured RF/PLL recovery over adding more generic
noise layers. Do not turn nominal head count into a signal-quality multiplier.

## Renderer-recovery constraints

Preserve the new failure latch, bounded fallback, thread-local prepared-deck state,
manual Retry behaviour, crash diagnostics, and process/thread output-parity
regression. A native thread pool should report fatal job/worker failures to the
GUI once rather than resubmitting unusable jobs on every timer tick. The new
conservative frozen-app backend is a compatibility choice, not a performance
benchmark or a substitute for diagnosing native faults.
